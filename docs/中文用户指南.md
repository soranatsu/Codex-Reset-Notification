# Codex Reset Notification · 中文用户指南

## 开始使用

1. 将发布 ZIP 完整解压到自己有写入权限的目录。不要在压缩包中直接运行。
2. 双击 `启动.cmd`，或打开 `Windows/CodexResetNotification.exe`。程序默认停止监测。
3. 在“监测与提醒”选择时区。中国大陆可填 `Asia/Shanghai`。设置轮询间隔，最低 60 秒，默认 300 秒。
4. 填写接口识别联系信息，例如自己的 `mailto:联系邮箱` 或 HTTPS 主页。该信息会随 User-Agent 提供给数据源；请使用愿意公开给数据源的联系信息。示例 `mailto:author@example.invalid` 为虚构地址，实际监测应填写自己的联系信息。
5. 在“通知配置”填写邮件或可选 Bark。保存配置，运行“模拟通知测试”确认本地队列流程，然后自行选择是否发送真实测试。
6. 点击“开始监测”。第一次完整且新鲜的成功检查只建立历史基线，不推送历史公告。之后跟踪新公告和生命周期变化。

数据及来源链接在“公告与批次”、详情和每条通知中显示：Data: [codex-reset.com](https://codex-reset.com/)。不需要 OpenAI 或 X 账户登录，不会读取本人额度或重置卡库存。

## SMTP 邮件

启用邮件后填写服务器主机名、端口、加密方式、通知账户／SMTP 用户名、密码／应用专用密码、发件邮箱和收件邮箱。多个收件地址用分号隔开，最多 30 个，每人单独发送。示例地址 `sender@example.invalid`、`one@example.invalid`、`two@example.invalid` 均是虚构地址，必须换成自己的。

按邮箱服务的官方 SMTP 指引选择 STARTTLS 或 SSL/TLS；通常对应 587 或 465，但以供应商说明为准。证书始终验证，不允许跳过验证。“无 TLS”仅允许不登录的 SMTP；不得用它发送账号密码。未加密服务器可看到邮件内容，不推荐在公网使用。

默认不保存密码，进程退出后须重新输入。只有勾选“授权保存到 Windows 凭据管理器”并保存配置后才持久保存。本程序只访问自己专属的两个凭据项，不读取浏览器密码、不枚举其他程序的凭据。同一 Windows 用户下的其他进程可能读取通用凭据，不能承诺对恶意软件保密。

已保存凭据的密码框留空并再次保存会保留已有值。要更换凭据，输入新值后保存。取消保存勾选再保存，会删除系统保存项并仅保留当前会话值；退出后消失。若系统凭据存储失败，程序不会改成明文保存。配置保存跨两个存储系统的失败可能需要用户核对自己的凭据项，再重新输入。

“发送真实测试…”会显示实际收件地址和 Bark 服务器，只有确认后才连接通知服务器。开发测试没有发送真实邮件。选择真实测试只处理本次测试条目，不会顺带发送其他待发公告。

## Bark

可选启用 Bark，填写 HTTPS 服务器主机地址和设备密钥。默认服务器为 `https://api.day.app`；自建服务器也必须使用 HTTPS，地址不要包含密钥、路径或查询参数。密钥通过 HTTPS POST 请求体发送，不放在 URL 中。

密钥保存授权与 SMTP 密码分开。通知采用普通 active 级别，声音和显示由 Bark、iOS、系统权限及网络状况决定；不能强制突破静音或专注模式。Bark 服务器确认接受也不证明手机已经显示通知。

## 公告类型和批次

| 界面状态 | 含义 | 是否停止该批定时提醒 |
| --- | --- | --- |
| 全局重置预告 | 明确公开预告，尚未完成 | 否 |
| 全局重置已获公开确认 | timeline 的 reset/announced 且没有未来窗口 | 是 |
| 可留存重置卡公告 | 发放卡的公告，不能当作额度重置 | 否 |
| 重置卡发放进展 | 同批次的明确 ETA 或发放中证据 | 否 |
| 官方报告重置卡可用 | 官方来源及 available 状态确认公共发放 | 是，仍须自行核对本人账户 |
| 第三方监测账户到账 | 数据源自己的观察 | 否，不证明本人到账 |

不使用预测概率、投票、玩笑或普通回复触发重置通知；不访问收费 X API。不会因截止时间到达就推断完成，也不会自动领取或消耗重置卡。

同一批按原始帖子 ID、回复链和生命周期去重。可选的回复元数据消失时，程序会保守地少关联，不猜测关联。未提供明确原帖关联的观察单独显示，不能按日期合并为已完成批次；因此缺乏明确关联证据时可能需手动停止旧批次。

首次基线中的历史待完成批次默认不启动每日提醒。确实想跟踪某一历史批次时，在界面选中它并点击“关注选中批次”。若本人已核对到账或不想继续提醒，可选“停止该批提醒”。这只改变本机提醒开关，不修改公开证据状态。

## 每日提醒

默认在所选时区每天 12:00、18:00，对已关注且尚未明确完成的批次发送额外提醒。时刻可用逗号分隔编辑，最多 12 个，格式为 HH:MM；也可关闭全局额外提醒。

每个当地日期、时刻、批次、通道和收件人只排队一次，夏令时重复小时也不会双发。当前实现按一分钟窗口判断，恢复运行后只补当前 30 分钟内的时刻，错过更早时刻不集中补发。未发送的定时提醒超过 30 分钟有效期后取消。

公开完成证据会关闭该批提醒，并取消它旧的待发进展／提醒，只保留新的完成通知。已经发送或处于确认丢失状态的通知无法撤回。来源过期或断网时暂停新的定时提醒，恢复后重新检查仍可取得的历史。

## 发送队列与日志

| 状态 | 意义及操作 |
| --- | --- |
| 待发送 | 已持久保存，等待运行和通道可用 |
| 退避重试 | 确定失败后等待，最多自动尝试 8 次 |
| 服务器已接受／送达未确认 | SMTP 返回 250 或 Bark 确认接受；不是收件或阅读回执 |
| 确认丢失／需核对 | 发送期间断线、未知结果或进程退出，不自动重发 |
| 受阻／需处理 | 永久拒绝、凭据缺失或重试次数耗尽，处理后人工重新排队 |
| 已取消 | 用户停止、过期或已有明确完成证据 |

SMTP 每个收件人单独保存结果，失败的人重试时不会重发给已接受的人。退避从 60 秒开始，最长常规间隔 3600 秒；若服务提供更长 Retry-After，则等待更长时间。公开接口也使用持久化轮询门限，重启不会绕过一分钟限制。

确认丢失的通知可能已经送达。选择“重新排队选中项…”前应核对收件情况，人工重试可能重复。重新排队仅改变状态，之后开启监测才会发送。日志只记录安全的状态文字和错误代码，不记录密码、设备密钥、HTTP 请求体或原始异常文本。

## 数据目录和退出

普通启动的本机目录为 `%LOCALAPPDATA%\ResetNotice`，包含 `config.json`、`state.sqlite3` 及 SQLite 辅助文件。配置包含邮箱和用户备注，队列包含收件邮箱及公开公告，请不要公开上传。凭据存放在系统中，配置只保存是否授权持久保存的标志。

关闭窗口会停止监测；已开始的网络请求可能等待约 40 秒结束，已开始的发送不能撤回。最小化后只要进程仍运行就继续工作。没有系统服务或默认托盘常驻。

用户可主动点击“启用登录开机启动…”。确认后只写当前用户的 `HKCU\Software\Microsoft\Windows\CurrentVersion\Run\ResetNotice`，登录后打开程序并开始监测。取消保存的凭据不能在重启后自动恢复，通知会受阻。移除入口只删除本软件的启动项。

电脑关机、睡眠、离线时无法保证实时监测。本机恢复后补查公开接口仍提供的历史，接口已移除的公告无法恢复。为了继续保留基线、去重和队列，升级程序时保留本机数据目录。不要同时开多个数据目录进行真实推送；默认同一目录有单实例保护。

如需卸载，先移除本软件启动项，在配置中取消两项保存授权并保存，退出程序，再删除程序解压目录。确认不需要历史后才删除本机数据目录。更改 `--data-dir` 会改变本软件的系统凭据命名空间，旧目录的凭据应在旧目录配置中清理。
